CloudGenie Auth Platform - User Guide

Overview

CloudGenie Auth is an Authentication-as-a-Service platform. It handles user identity, authentication, organizations, and OAuth2 client credentials so your applications can focus on their own domain logic.

This test console lets you exercise every API endpoint interactively. Tokens are stored in-browser and attached to authenticated requests automatically.

Quick Start

  1. Test Connection — Click the Test Connection button in the top bar to verify the API is reachable.
  2. Register — Go to Register, enter an email and a strong password (min 12 chars, must include upper + lower + digit + special character). Optionally provide a display name and an organization name.
  3. Verify Email — Check your inbox for a 6-digit OTP code. Go to Verify Email, enter it, and click Verify. If the code expired, use Resend Code.
  4. Login — Go to Login, enter your credentials. On success, the access and refresh tokens are stored automatically (visible in the bottom bar).
  5. Use Authenticated Endpoints — All sidebar items under Authenticated, Organizations, Applications, and Admin will automatically include your access token.

Authentication Flows

Email + Password

  1. Register → Verify Email (OTP) → Login → receive token pair
  2. Access token is short-lived; use Refresh Token to get a new pair
  3. Call Logout to invalidate the refresh token

OAuth (Google / Microsoft)

  1. Click Login with Google or Login with Microsoft
  2. Complete consent in the popup window
  3. On redirect, tokens are exchanged automatically. If it fails, use OAuth Callback to manually exchange the authorization code.

Client Credentials (App-to-App)

  1. Register an Application under an organization (see below)
  2. Use the Client Token panel with the issued client_id and client_secret
  3. The returned access token represents the application, not a user

Password Reset

  1. Go to Password Reset Request and enter the account email
  2. Check your inbox for a 6-digit OTP
  3. Go to Password Reset Confirm, enter email + OTP + new password
Password reset OTPs expire after 15 minutes. Rate limited to 5 requests per hour.

Organizations

Organizations are multi-tenant containers. Every user belongs to at least one.

  • Create Org — Creates a new organization. You become its Admin.
  • List Orgs — Shows all organizations you belong to.
  • Invite User — Sends an email invitation to join your org (Admin only).
  • Accept Invitation — Paste the invitation token to join an org.
When logging in, you can optionally pass an Org ID to scope your session to that organization. This affects the org_id claim in your access token.

Applications (OAuth2 Clients)

Register external applications that authenticate via client credentials. This is how consuming apps integrate with the platform.

  • Register App — Creates a new application under an org. Returns a client_id (prefix cg_) and client_secret (prefix cgs_).
  • List Apps — Shows all applications registered under an org.
  • Rotate Secret — Generates a new client secret and invalidates the old one.
  • Delete App — Permanently removes an application.
  • Client Token — Exchanges client_id + client_secret for an access token.
The client_secret is only shown once at creation (or rotation). Store it securely — it cannot be retrieved later.

Scopes & Permissions

Access is controlled by scopes embedded in the JWT. Users get scopes based on their role; apps get scopes set at registration time.

Member profile:readprofile:writeorgs:readusers:readapps:read
Read-only profile:readorgs:readusers:readapps:read

When requesting a Client Token, you can optionally request specific scopes. The granted scopes will be the intersection of what you request and what the application is allowed.

Admin Operations

Admin endpoints require an access token with admin:users:read or admin:users:write scopes (Admin role only).

  • List Users — View all users across the platform.
  • Disable/Enable User — Suspend or reactivate a user account by UUID.
